La sesión tiene por objeto poner en funcionamiento, de principio a fin, una primera versión de la célula de agentes descrita en la propuesta del alumno. El resultado esperado no es un sistema terminado, sino una estructura mínima que funcione sobre un modelo de lenguaje instalado en la propia computadora, y que se desarrollará por etapas entre noviembre de 2026 y marzo de 2027.

La guía no supone conocimientos previos de programación. Cada paso indica qué escribir, qué debe aparecer en pantalla y cómo interpretarlo.

La implementación se rige por tres principios metodológicos:

  1. El modelo de lenguaje identifica y señala fragmentos; el conteo de frecuencias lo realiza el programa de forma exacta; la interpretación corresponde al investigador.
  2. Todo hallazgo del modelo debe sustentarse en una cita textual, cuya existencia en la fuente se comprueba de forma automática.
  3. Todo el procesamiento ocurre en la computadora del investigador; el corpus no se envía a ningún servicio externo.

4. Instalación paso a paso

Convención de esta guía: el texto en recuadro gris se escribe en la terminal tal cual y se ejecuta con Enter. Si algo no coincide con lo descrito, consulte la sección 7, Problemas frecuentes.

Paso 1. Instalar Ollama y descargar el modelo

Descargue Ollama desde ollama.com e instálelo como cualquier aplicación. Al abrirlo aparece un ícono en la barra superior de la pantalla. Después abra la aplicación Terminal (Aplicaciones → Utilidades) y escriba:

ollama pull qwen3:14b

La descarga ocupa alrededor de 9 GB y puede tardar varios minutos. Si se interrumpe, basta con repetir el comando: continúa desde donde quedó.

Criterio de selección: el modelo no debe ocupar más de la mitad de la memoria RAM del equipo (menú Apple → Acerca de esta Mac). Con 16 GB se recomienda qwen3:8b; con 32 GB o más, qwen3:14b.

Paso 2. Comprobar el modelo

ollama list

Debe aparecer una línea con el nombre del modelo, por ejemplo qwen3:14b. Para probarlo:

ollama run qwen3:14b "Di hola en una palabra"

La primera vez puede tardar hasta dos minutos, porque el modelo se carga en memoria. Primero aparece un texto entre Thinking... y ...done thinking, que es el razonamiento del modelo, y al final la respuesta. Si al terminar aparece >>>, se sale escribiendo /bye.

Paso 3. Colocar el proyecto en la computadora

  1. Descargue contramaquina.zip y haga doble clic sobre él en la carpeta Descargas. Se crea la carpeta contramaquina.
  2. Mueva esa carpeta a Documentos.

Paso 4. Abrir el proyecto en VS Code

  1. Abra VS Code y elija File → Open Folder… (Archivo → Abrir carpeta…). Seleccione la carpeta contramaquina.
  2. Si el programa pregunta si confía en los autores, elija Yes, I trust the authors.
  3. Abra la terminal integrada desde el menú Terminal → New Terminal. Aparece en la parte inferior de la ventana y ya está situada dentro de la carpeta del proyecto.

Paso 5. Comprobar Python

python3 --version

Debe aparecer un número de versión igual o superior a 3.10, por ejemplo Python 3.14.5.

Paso 6. Crear y activar el entorno virtual

python3 -m venv .venv
source .venv/bin/activate

El primer comando no muestra nada; es lo esperado. Tras el segundo, la línea de la terminal debe comenzar con (.venv).

Cada vez que se cierre VS Code y se abra una terminal nueva, debe repetirse source .venv/bin/activate. Sin (.venv) al inicio de la línea, los comandos siguientes fallan.

Paso 7. Instalar las librerías

pip install -r requirements.txt

Se muestra mucho texto durante uno o dos minutos. La instalación fue correcta si las últimas líneas dicen Successfully installed y no aparece la palabra ERROR.

Paso 8. Verificar el nombre del modelo

Abra config.yaml desde la lista de archivos. La línea modelo: "qwen3:14b" debe coincidir exactamente con el nombre que mostró ollama list. Si se descargó otro modelo, corrija el nombre y guarde con Cmd + S.

Paso 9. Probar la conexión entre Python y el modelo

python llm.py

En menos de un minuto debe aparecer una respuesta con dos campos:

concepto='Análisis crítico del discurso' definicion='Enfoque que estudia cómo el lenguaje...'

Este resultado confirma lo esencial: el modelo responde y respeta la estructura que se le exige. Puede ocurrir que el contenido de cada campo no sea el esperado (por ejemplo, una definición en el campo concepto). El modelo sigue la forma con exactitud, pero interpreta el contenido; por eso cada categoría del libro de códigos requiere instrucciones precisas.

5. Desarrollo de la sesión

Actividad 1. Recorrido en modo simulado (10 min)

CONTRAMAQUINA_SIMULAR=1 python pipeline.py

En este modo el programa no usa el modelo: inventa respuestas para comprobar que las etapas se comunican entre sí. Termina en segundos y muestra las etapas [01] a [05]. En la carpeta salidas conviene revisar dos archivos:

  • resumen.md (clic derecho → Open Preview): tablas de conteo por categoría, fuente y mes. Los números carecen de significado; interesa la forma del resultado final.
  • 02_descartes_alucinacion.jsonl: el simulador atribuye deliberadamente a un documento la frase “Esta frase no existe en ninguna fuente del corpus”. El verificador no la encuentra en el original y la descarta. Este es el mecanismo que protege el análisis frente a las alucinaciones del modelo.

Actividad 2. Primer análisis con el modelo (20 min)

El proyecto incluye dos notas ficticias en corpus/raw/, redactadas para contener mecanismos reconocibles. Se usan para la primera prueba antes de incorporar documentos reales.

python pipeline.py --etapa decodificar
python pipeline.py --etapa n1
python pipeline.py --etapa reporte

El primer comando prepara los textos. El segundo ejecuta al Analista de nivel 1, que tarda entre 30 segundos y 2 minutos por documento. El tercero genera las tablas; debe indicar (usando 02_hallazgos_n1.jsonl).

Abra salidas/hallazgos.xlsx desde el Finder con Excel o Numbers. Cada fila es un hallazgo:

ColumnaContenido
categoriaMecanismo que el modelo cree haber encontrado
citaFrase textual del documento
enunciadorQuién la enuncia: autoridad, medio, testigo
justificacionRazón por la que el modelo asigna la categoría
verificacionexacta si la cita aparece literalmente; aproximada si es casi idéntica (debe contrastarse con la columna pasaje_real)

La lectura de esta tabla es trabajo del investigador. Las preguntas guía son: ¿la categoría asignada es correcta?, ¿hay mecanismos presentes en el texto que el modelo no detectó?, ¿alguna cita aproximada altera el sentido del original?

Actividad 3. Elaboración del libro de códigos (30 min)

El archivo codebook.yaml contiene cuatro categorías de nivel 1 y tres de nivel 2 a modo de plantilla. El alumno debe reformularlas desde su marco teórico (Gutierrez Aldrete, 2022; Missiatto, 2021; Mbembe, 2011). Cada categoría requiere una definición operativa, criterios de inclusión, criterios de exclusión y al menos un ejemplo. Preguntas orientadoras:

  1. ¿Qué criterio distingue la criminalización de la víctima del reporte neutral de una línea de investigación?
  2. ¿Qué mecanismos documentados en la literatura no están representados; por ejemplo, la desacreditación de la labor periodística o activista?
  3. ¿Qué casos límite deben consignarse expresamente como exclusiones?

El formato YAML es sensible a la sangría (los espacios al inicio de cada línea). Al editar, conviene copiar una categoría existente y modificar su contenido, conservando la misma alineación. Cada versión del libro de códigos debe guardarse con numeración (v1, v2…), ya que su evolución forma parte del registro metodológico de la tesis.

Actividad 4. Incorporación de documentos reales (20 min)

Se sustituyen las notas ficticias de corpus/raw/ por dos o tres documentos del corpus real (véase la sección 8). Los archivos deben nombrarse con el formato AAAA-MM-DD_fuente_descripcion, por ejemplo 2015-08-02_eluniversal_nota.pdf, porque de ese nombre el programa obtiene la fecha y la fuente. Después se repiten los comandos de la Actividad 2. Con documentos extensos conviene limitar la prueba a tres fragmentos:

python pipeline.py --etapa n1 --limite 3

Los PDF escaneados (imágenes sin texto seleccionable) quedan señalados con un aviso: requieren reconocimiento óptico de caracteres (OCR), pendiente para una fase posterior.

Actividad 5. Ajuste iterativo (tiempo restante)

El ajuste consiste en modificar una sola variable por vez y repetir el análisis sobre los mismos documentos, para poder atribuir cada cambio en los resultados a una causa identificable.

VariableUbicación
Definiciones, criterios y ejemploscodebook.yaml
Instrucciones generales del analistaSección SISTEMA en agentes/analista_n1.py
Modelo de lenguajeconfig.yaml, campo modelo
Tamaño de los fragmentosconfig.yaml, sección fragmentos

Si el tiempo lo permite, se ejecutan las etapas restantes: python pipeline.py --etapa n2, luego --etapa evaluar y finalmente --etapa reporte. El reporte usa siempre el archivo de hallazgos más reciente.

Criterio de validación

La fiabilidad de la codificación automática se establece con el coeficiente kappa de Cohen (1960), que mide el acuerdo entre la codificación del investigador y la de la célula descontando el acuerdo que se produciría por azar:

κ = (po − pe) / (1 − pe)

donde po es la proporción de acuerdo observado y pe la proporción de acuerdo esperado por azar. Procedimiento:

  1. Cada ejecución del reporte genera validacion/muestra_para_codificar.xlsx, con hasta 30 citas al azar y sin la categoría asignada por el modelo, para no influir en el juicio del investigador.
  2. El investigador abre el archivo en Excel, escribe en la columna categoria_humana el identificador de la categoría que corresponde a cada cita (por ejemplo, CULPABILIZACION) o NINGUNA si la cita no debió marcarse, y guarda.
  3. En la terminal se ejecuta python validacion/kappa.py, que muestra el acuerdo simple, el coeficiente kappa y una tabla de coincidencias y discrepancias.

Se propone como umbral un kappa igual o superior a 0.61, que corresponde a un acuerdo sustancial según Landis y Koch (1977), antes de procesar el corpus completo. El registro de este coeficiente en cada versión del libro de códigos documenta la fiabilidad del instrumento ante el comité de tesis.

La muestra se regenera cada vez que se ejecuta el reporte. Antes de codificarla, conviene guardar una copia con otro nombre para no perder el trabajo.

8. Constitución del corpus

La carpeta de investigación del Caso Narvarte no es de acceso público. Desde 2015 la autoridad ministerial la mantuvo en reserva, y el acceso ha correspondido a las familias y a su representación legal; Artículo 19 la consultó en su calidad de representante de Rubén Espinosa. Las piezas que circularon públicamente en 2015, entre ellas declaraciones de testigos y primeras actuaciones ministeriales, lo hicieron mediante filtraciones atribuidas a servidores públicos de la entonces Procuraduría, que fueron objeto de sanción y de un juicio de amparo promovido por la familia de Rubén Espinosa.

Esta restricción no compromete el objeto de estudio. El necrodiscurso se manifiesta en los enunciados públicos de autoridades y medios, no en el expediente; en consecuencia, el corpus pertinente está integrado por fuentes de acceso público.

Vías para ampliar el corpus:

  1. Contacto con Artículo 19, en su calidad de coadyuvante, para solicitar orientación sobre documentos públicos o versiones testadas.
  2. Solicitud de acceso a la información a la Fiscalía General de Justicia de la Ciudad de México, requiriendo la versión pública de boletines y comunicados de 2015 relativos al caso. Una eventual negativa constituye, en sí misma, un dato pertinente para la investigación.
  3. Solicitud de las versiones públicas de las sentencias de las personas condenadas ante el Poder Judicial de la Ciudad de México.

9. Consideraciones éticas

Las filtraciones de 2015 incluyeron fotografías y datos de la vida privada de las víctimas. La circulación previa de ese material no lo vuelve apto para su reproducción. La célula se limita al análisis de los enunciados de autoridades y medios: no recolecta ni almacena imágenes de las víctimas ni datos personales ajenos a las citas analizadas.

El procesamiento local responde a la misma consideración, ya que evita la transmisión del corpus a servicios externos. Las dos notas de prueba incluidas en el proyecto son ficticias y no deben citarse como parte del corpus.
